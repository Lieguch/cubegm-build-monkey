* 两条流水线（`rkgame-rebuild`×2、`1to1-linux-gates`）**全部死在 `Prepare`**，

### 根因：**触发条件本身在烧配额**

`.cnb.yml` 里 3 条流水线**都挂在 `push` 下、且没有任何 `if` / `ifModify` 守卫**
⇒ **每次 push 到 main 都跑 3 条 8 核重活**（apt 装 ARM 工具链 + 引导 sysroot + 构建 + 模拟器测试）。

### 修法（已写好，**未应用**：文件被并行会话占用）

补丁脚本：**`build/_attic/_patch_cnb_triggers.py`**（一行执行即可）

* **依据**（官方触发规则页，已联网核实）：`api_trigger` / `api_trigger_*` 是合法事件名；
  `cnb build start-build --event` 要求「须为 api_trigger 或以它开头」⇒ 用 `api_trigger_rebuild`
  与 `api_trigger_gates` **精确选条**。
* **改法**（只改「挂在哪个事件下」，**3 条流水线的 `stages` 一字不动**）：
  * `push:` → 只留 `ci-sanity`（秒级：全部 `tools/*.sh` 的 `sh -n` + 全部 `tools/*.py` 的 `py_compile`
    + `.cnb.yml` 可解析）
  * 两条 `rkgame-rebuild` → `api_trigger_rebuild:`
  * `1to1-linux-gates` → `api_trigger_gates:`
* 备份：`build/_attic/_cnb.yml.bak`

### 平台事实（实测，供你评估要不要继续用 CNB）

* CNB **交互式工作区**会在会话中途**重启容器**（实测 `up 3 min`）⇒ `/tmp` 被清空；
  用完即回收（`WORKSPACE_NOT_FOUND`），重启后 SSH 地址（含 UUID）变化。
  ⇒ 上传与执行**必须在同一次 SSH 连接内**完成（`tar czf - | ssh '… && tar xzf - && 跑'`）。
* 该工作区**无预装** `binutils-arm-linux-gnueabihf` / `pyelftools`，需现场 apt/pip。
* ⇒ 结论与你既定的方向一致：**长任务走声明式流水线**，别在交互式会话里硬扛。

## 三、本会话在 1:1 主线上真正推进的部分（与上面两个阻塞无关）

### 3.1 三条**构建事实**（全部单变量实测，可复现）

| # | 事实 | 判定方法 | 旧的我们 |
|---|---|---|---|
| 1 | 工厂用**真 glibc 2.24 头** | zig 头 → `putc`/`getc`；真头 → **`_IO_putc`/`_IO_getc`** | zig 自带 glibc 头 |
| 2 | 优化档 **≥-O1 且非 -Os** | 真头 `-Os` → `strdup`；真头 `-O1/-O2` → **`__strdup`** | `-Os`（专有）/ `-O1`（上游） |
| 3 | `strcmp(x,"字面量")==0` → **`bcmp`** 是 **clang 独有**变换（GCC 不做） | 同源默认 → `bcmp`（`r2=长度+1`）；`-fno-builtin-strcmp` → `strcmp` | 未加该开关 |

**文档级依据**（真头逐行）：`stdio.h:587` 把 `putc` 定义为**无条件宏** `_IO_putc`（与优化档无关）；
`bits/stdio.h:79` 的 `putchar` 是 **extern-inline**（受 `__OPTIMIZE_SIZE__` 门控）。

★ **推论（新）**：工厂**同时**导入 `putchar` 与 `_IO_putc` ⇒ 它的构建是 **per-TU 优化档**：
* **应用代码 `-Os`**（实证：`UpdateROM.c` 真头 `-Os` → `putchar`；真头 `-O2` → `_IO_putc`）
* **上游 mxml 等 `-O2`**（要 `__strdup` 必须 extern-inline 开）
* **libiconv `-O0`**（已由代码形态普查定案，304/304 与 Thumb 同一集合）

### 3.2 头集合的**顺序**必须正确（两次失败换来的）

```
组件自己的 -I  →  GCC include  →  GCC include-fixed  →  sysroot/usr/include
```
| 失败 | 原文 | 原因 |
|---|---|---|
| 1 | `undefined symbol: libiconv_close` / `field has incomplete type 'struct iconv_fallbacks'` | `-I<glibc 头>` 排在组件自己的 `-I` 之前 ⇒ 盖住 libiconv 自己的 `iconv.h` |
| 2 | `error: function-like macro '__GLIBC_USE' is not defined` | 真 glibc `limits.h` 的 `#include_next` 跳进 **zig 自带的更新版 glibc `limits.h`**（`-nostdinc` 挡不住 zig 注入的内建头） |

实测（`-O2` + 该头集合）：`mxml-file.c` 未定义 = **`_IO_getc`/`_IO_putc`/`__strdup`**（= 工厂）；
`localcharset.c` 未定义 = **`nl_langinfo`**（= 工厂）。

### 3.3 仪器（尺子）真缺陷修复

| 缺陷 | 证据 | 修法 |
|---|---|---|
| `libc_model.ALIASES` 漏 **`_IO_putc`** | 模型只建了 `_IO_getc` ⇒ 工厂侧这条调用**只有一侧被建模** | 补 `_IO_putc → putc` |
| 漏 **`bcmp`** | clang 变换产生；工厂侧是 `strcmp` | 补 `bcmp → memcmp` |
| **一条已腐烂的自证锚点** | 旧代码用手写 `impl = {… 'getc'}` 断言"别名目标都被实现"，而模型**根本没有 getc 处理分支** ⇒ **断言恒真、从未生效** | 改为**从模型源码机械推导**已实现名 + `NOT_MODELLED` 显式列出 |

自证：`libc_model --self-test` **34 → 37 条，失败 0**。

**新门禁**：`tools/model_coverage.py`（**单侧未建模**，接进 `link_full.sh`，**exit 19**）+
台账 `tools/model_asymmetry_ledger.txt`（棘轮，现 10 项各带原因）。

### 3.4 工具缺陷修复

* `link_full.sh`：XUnzip 对象缺失时**静默跳过**（`[ -f … ] &&`）⇒ 链接报一堆
  `undefined symbol: TUnzip::*`，把「某个 `.o` 根本没编出来」伪装成链接问题 ⇒ 改 **fail-closed（exit 12）**。
* 实验脚本：zig 全局缓存**按臂隔离**（8 路并行共享同一缓存会报 `error: CacheCheckFailed`）。
