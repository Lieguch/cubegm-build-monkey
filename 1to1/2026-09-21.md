- ★★★★★ **四条"仪器自身的静默失效"（本轮全部当场踩到并修掉）**：
  ① **连续两次 `write` 用同一原始串** ⇒ 第二次**覆盖**第一次的替换，而脚本**照样打印 ✓**
     ⇒ 地址清单被静默丢弃。纪律：累积替换、**最后只写一次**；**写完必须读回 grep 校验**。
  ② **shell heredoc 把 `\\` 变 `\`** ⇒ Python 三引号里 `\<换行>` 是**行接续**（吞掉换行）
     ⇒ 锚点**永远**匹配不上。纪律：带反斜杠的补丁脚本**写成文件再执行**。
  ③ **关键地址必须 8 位十六进制**：写 6 位 `010fec` ⇒ `grep "/010fec/"` 与轨迹里的
     `/00010fec/` 不相等 ⇒ **恒 0 命中**；而"0 命中"**看起来恰好等于**"分支没走到"
     ⇒ **把结论带向完全相反的方向**。纪律：一律 `'%08x' % addr`。
  ④ **0 命中必须有阳性对照**：0 命中 = ①没走到 或 ②普查链路坏了，没有对照**分不清**。
     本项目天然阳性对照 = `00017dac`(mui_LoadUIResource 入口) / `00012ebc`(FindZipItemA 入口)。
- ★ 共性：**"看起来正常"的输出最危险** —— 这四条都不是报错，而是给了"读起来合理、
  但方向相反"的结论。通则：新仪器/新判据上线必须 ①**正负双向锚点**自证；
  ②**产物与写入分离校验**；③关键量**必须有阳性对照**。

- **shell 环境损坏的绕过路径**：当 dirname/git/grep/ls/tail/cd 全不可用时，用 python -c + subprocess.run + 工具绝对路径（`C:\Users\Administrator\.workbuddy\binaries\PortableGit\versions\1.2.0\cmd\git.exe`）+ os.chdir() 可绕过所有 PATH 问题；credential helper 交互授权加 GIT_TERMINAL_PROMPT=0 + GCM_INTERACTIVE=Never 可强制非交互，实测能推 CNB
- **Edit 工具静默失败**（复现 Sprint 6 教训）：批量并行改 6 行映射表时，某些行因内容不完全匹配会静默失败 → 状态翻转批量编辑一律走 Python 脚本 + assert 逐条校验


### ★★★★★ 设备端诊断仪落地（用户确认"设备和 SD 卡都在"，要求日志开到最全）

**背景约束**：设备是游戏盒子（HDMI + 扬声器，**无命令行**）；启动链
`U-Boot→kernel→init→rcS→S80icube→icube→rkgame` **全是原厂文件（红线不可动）**
⇒ **没有任何地方能注入 `LD_PRELOAD`/环境变量** ⇒ 诊断能力必须**编进我们自己构建的 rkgame**。

**做法（全部链接/编译期开关，零源码改动）**：
| 手段 | 覆盖 | 实现 |
|---|---|---|
| `-finstrument-functions` | 每个函数进出 | 环形缓冲 65536 帧 × 12 B = 768 KB（`.bss`） |
| `-Wl,-wrap=<sym>` × 65 | 文件/ioctl/mmap/dlopen/线程/时间/信号 | `src/diag/cgm_wrap.c` |
| 崩溃捕获 | siginfo + 全寄存器 + fp 链 + 栈扫描 + maps + fd | 信号处理器内**只走 syscall** |
| 心跳 + 周期快照 | 区分"卡死"vs"崩溃"；断电也不丢最近历史 | 每 5 s 一次 |

**新增文件**：`src/diag/cgm_diag.{h,c}`、`src/diag/cgm_wrap.c`、`tools/build_diag.sh`、
`tools/diag_wraps.sh`、`tools/diag_symbolize.py`、`tools/stage_sd_diag.py`、
`tools/_diag_gate_selftest.py`、`DIAG-RUNBOOK.md`；`tools/link_full.sh` 加**不影响默认行为**的
3 个扩展点（`DIAG_OBJD` / `DIAG_XUNZIP` / `DIAG_EXTRA` / `DIAG_LDFLAGS`）。

**产物**：`build/rkgame.diag` = 17,379,704 B（交付版 17,331,448 B，+48 KB），ABI 全 PASS，
7 个诊断符号全部落进产物，sha256 前 16 = `5a429cfc32a87f67`。
**投放目录**：`_sdcard_drop/`（含 `READ-ME-FIRST.txt` 全套步骤 / `DEPLOY-MANIFEST.txt` 含 sha256）。

**本轮四处新发现（已落 GAP）**：
1. **16.65**：zig 驱动层**只认单横线 `-Wl,-wrap=`**，不认 `--wrap=`（实测七种写法）。
   行为自证：加 wrap 后 `open` 从产物未定义符号里**消失**。
2. **16.66**：设计门禁的"缺陷态"**必须用被引用的符号** —— `-wrap=X` 只在有东西引用 `X` 时
   才产生未定义符号；我第一版用无人引用的假符号 ⇒ **假绿**（exit 0、照常出产物）。
   换成被引用的 `fflush` 后门禁如期 exit 11。
3. **16.67**：门禁自身踩了"原生程序只认 Windows 形式路径"这条老坑（`ROOT` 是 `/d/...`，
   原生 python 打不开）⇒ 判据恒假。**救场的是门禁里"读不到文件也必须 exit 11"的守卫**。
4. **16.68**：`WRAPS` 清单与实现必须一一对应（实测漏 6 个 ⇒ `undefined symbol`）；
   自检门禁从 [4/5] **前移到编译之前**（旧位置要先白编 213 个文件 ≈ 2 分钟）。

**符号化工具自证**：造合成 `frames.bin`（含真实符号地址 + 1 个越界地址）
⇒ 6 个函数被正确解析、调用树按深度缩进；并因此**抓出工具自身一个精度缺陷**
（越界地址被张冠李戴成 `_fini(+0x39f79970)`）⇒ 已改为"超界一律判 `?` 并单列"。
