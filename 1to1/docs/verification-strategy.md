# 验证策略（经实测修正）

> 本文记录 **2026-09-10 夜** 对验证门禁的实测结论与策略修正。
> 所有结论都有 CI 实测数据支撑，**不是推测**。

---

## 一、原定门禁与实测结果

| 门禁 | 定义 | 要求 | 实测结果 |
|---|---|---|---|
| **T1 汇编等价** | 归一化「助记符+操作数（符号化目标）」序列全等 | 需**同款编译器** | **不可达成**（见 §二） |
| **S1/S2 结构指纹** | 外部调用集 + 大立即数 + 基本块数 | 跨编译器鲁棒 | **不足以定版**（见 §三） |

## 二、T1 为何不可达成：工具链不可获取（实测）

原厂工具链 = `armv7a-libreelec-linux-gnueabi`（LibreELEC/Lakka 8.0 系，**glibc 2.24**，GCC ~6.x）

**获取途径逐一探测，全部失败**：

| 途径 | 探测结果 |
|---|---|
| `sources.libreelec.tv` | HTTP 200 但**内容为空**（len=0），无目录列表 |
| `sources.libreelec.tv/toolchain/` | **404** |
| `releases.libreelec.tv` | 仅重定向到 `libreelec.tv/downloads`（只有镜像，无 SDK） |
| `archive.libreelec.tv` | 连接被远端关闭 |
| LibreELEC 官方发布 | **不发布预编译 SDK/工具链**（其 SDK 需自行 `make` 构建） |
| `releases.linaro.org` GCC 6.x 直链 | 站点已迁移为 SPA，**所有路径返回 65 字节占位页**（非真实文件） |

**结论**：精确复现该工具链需从源码构建（LibreELEC 构建系统 + era-appropriate Ubuntu 16.04 容器，数小时）。
**当前不做**：成本高、不确定性大，且**非功能等价所必需**（见 §四）。

## 三、结构指纹为何不足：实测数据

`tools/ci_p2a_stb.py` 用结构语义指纹比对 stb_truetype（原厂可比函数 78 个）：

| 版本 | 候选函数 | S1 | S2 | S3 | FAIL |
|---|---:|---:|---:|---:|---:|
| v1.22 787f1d64 | 85 | 10 | 22 | 0 | 44 |
| v1.23 7a69424f | 90 | 10 | 22 | 0 | 44 |
| v1.24 e140649c | 90 | 10 | 22 | 0 | 44 |
| v1.25 be901954 | 90 | 10 | 22 | 0 | 44 |
| v1.26 6e9f34d5 | 90 | 10 | 22 | 0 | 44 |

**两个结论**：
1. **无法区分版本**——v1.22～v1.26 结果完全一致 → 这些版本间差异（bug 修复）在结构指纹粒度下不可见。
2. **通过率仅 41%**（32/78）→ 剩余 59% 的 FAIL 来自 **GCC 11 与工厂 GCC 6 的编译差异**（内联决策/大立即数布局），
   而非逻辑差异。**故结构指纹不能单独作门禁**（会把正确的实现判为 FAIL）。

> 修正过程（避免误判）：初版指纹未去 `@plt` 后缀，`.o` 内 `bl 0 <malloc>`（→`@malloc`）与可执行文件内
> `bl … <malloc@plt>`（→`@malloc@plt`）永不相等 → 通过率 8/78。去掉后缀 + 立即数分层（小立即数为栈偏移噪声）
> 后升至 32/78。**仍是噪声主导，不足以判定。**

## 四、★ 修正后的验证策略

判定标准是**语义级等价**（用户已确认，明确允许寄存器分配/指令调度差异）。
既然精确工具链不可得、代码级指纹噪声主导，**唯一可靠且直接对应目标的信号是行为**：

### 4.1 主门禁 = 行为差分（oracle 比对）

原厂二进制 = oracle。同一输入下比对**可观测输出**：

| 维度 | 方法 | 判据 |
|---|---|---|
| 帧缓冲 | 抓 DRM/KMS 输出帧（或 fb 快照） | 关键画面逐像素/感知哈希一致 |
| 日志 | 比对 rkgame.log 的语义事件序列 | 事件序列一致（时间戳/地址除外） |
| 文件写入 | 比对写入路径 + 内容哈希 | 存档/配置/快照文件语义一致 |
| syscall | `strace -f` 比对调用序列 | 关键调用序列一致 |
| 退出码 | 各入口（无参/`/JoystickTest`/`/USBJoystickTest`/autorun） | 全部一致 |

### 4.2 辅助门禁 = 结构指纹（限定用途）

**仅用于「我们自己的实现 vs 我们自己编译的参照」**——即控制变量后，
若两次编译使用同一工具链，结构差异才指示真实逻辑差异。
**不用于**与工厂二进制的绝对比较（§三）。

### 4.3 T1 汇编等价 —— 归档为「若日后取得工具链再启用」

工具链若日后可得（LibreELEC 源码构建 / 第三方镜像），T1 门禁可立即复用现有实现
（`tools/funcdump.py` + `tools/funcdiff.py` 已自检 100% T1）。

## 五、上游版本锁定：按「时代 + 覆盖率」证据裁定

既然尺寸/指纹均无法定版，改用**两条独立证据**：

| 证据 | 内容 | 指向 |
|---|---|---|
| **时代证据**（强） | 固件内容时间戳：`joystick.zip`=2022-10-29、`ui_ar.zip`=2023-02-06、`ui_cn/en.zip`=2023-03-02 | 构建窗口 **2022-10 ～ 2023-03** |
| | stb_truetype **v1.26 发布于 2021-08-28**，且直到 2024-07-15 未再发版 | 该窗口内唯一版本 = **v1.26** |
| **覆盖率证据** | v1.19～v1.26 **全部**覆盖原厂 81/81 函数 | 选择任一版本**功能风险为零** |

**裁定：stb_truetype = v1.26**（时代证据唯一指向，且符号覆盖完整）。
**残余风险**：若工厂实际使用更早版本，差异仅在 v1.22→v1.26 的若干 bug 修复（均为上游改进，不构成功能缺失）。
→ 由行为差分门禁兜底（§4.1）。

> **这一裁定不是猜测，而是在「精确不可判定」前提下的显式证据裁定 + 风险声明 + 兜底措施。**

## 六、对后续阶段的影响

| 阶段 | 原计划 | 修正后 |
|---|---|---|
| P2-A | 尺寸/指纹定版 | **时代+覆盖率证据裁定**，行为差分兜底 |
| P2-B | 函数级 T1 门禁 | **行为差分门禁**（T1 降为可选，工具有链后可选启用） |
| P3 | ABI 门禁 | 不变（ELF 头/`.interp`/`e_flags` 逐字段一致，**不依赖编译器版本**） |
| P4 | 行为差分 | **升为主门禁**，本策略 §4.1 落地 |
