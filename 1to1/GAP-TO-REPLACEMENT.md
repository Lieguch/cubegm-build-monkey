## 〇、一句话结论

**代码层面已接近收口（工厂函数 92.2% 已由我们自己的代码提供）；但"能否直接替代"这个论断目前是零实证 —— 因为重建产物从未在设备上跑过（N6 真机验收从未做）。**

- 真正的短板**不是代码**，而是**验证**：沙箱里工厂侧自己就崩（无法当参照），真机又没试过。
- 因此现在的状态准确表述是：**"应该能跑，但没人验证过能不能跑"**。

## 三、符号落位算法（本轮新增的可复用刻度）

```
① 读工厂 symtab：每个 FUNC 名 → (st_value, st_size)            [804 个]
② 读重建产物 symtab：同名符号的 st_value
③ 判归属：
   落在产物 .text（VMA 0x5000000）      ⇒ 已由我们重编
   落在产物 .fimg_text（工厂原码，0x9b10 起）⇒ 仍未替换
```

实测结果：

| 归属 | 个数 |
|---|---|
| ★ 已由我们重编（`.text`） | **741** |
| 仍指向工厂原码（`.fimg_text`） | **0** |
| "缺失" | 63 |

那 63 个几乎全是 GCC 生成的**特化符号**（`.constprop.N` / `.isra.N` / `.part.N`），例如
`run_process.constprop.0`、`TUnzip::Get.part.5`、`mxml_isspace.part.0`、`stbtt__find_table` ——
**不是真缺失**，功能已由基函数提供。

| 项 | 现状 | 是否阻塞"直接替代" |
|---|---|---|
| **N6 真机验收** | 从未在设备上部署过重建产物 | ★★★ **决定性阻塞** |
| **观测窗口（沙箱）** | 沙箱下**工厂侧**读不出 UI 资源包 ⇒ 工厂 9 场景 `exit=139`，我们 `exit=124`；菜单/游戏/存档路径**无法逐项对照** | ★★★ 阻塞**验证**，不阻塞功能（已判定我们侧不是缺陷） |
| 8 个静态 WARN | `popwindows` 0.552 · `ReadUSBJoy` 0.476 · `GetZipItemA` 0.654 … 疑编译器分段，**未核** | 否（但须核） |
| 2 个 MISSING | `code_convert.constprop.22` · `mui_outputxy_length.isra.19` | 否（特化符号） |
| `DT_NEEDED` | 我们少 `libstdc++.so.6` / `libgcc_s.so.1`（工厂 7 个，我们 5 个） | 否（已登记可接受差异：我们未用 C++ 异常/RTTI） |
| 产物体积 | **17,331,448 B** vs 工厂 3,921,108 B | 否，但需注意：差异 = ①嵌入的工厂镜像 `.fimg_*`（≈3.8 MB）②**节间 11.6 MB 空洞**（`.text` 排在 VMA `0x5000000`）③符号表 |
| 已登记的保真度差异 | 工厂 `lufread` 内存分支的 `spi_memcpy` 运行期开关（工厂侧是**空 4 B 函数**），我们硬编码 `memcpy` | 否（只在 `flags==1` 走；`ui_cn.zip` 走 `fopen` 的 FILE\* 分支） |

### ★ 观测窗口瓶颈的精确链路（本轮定案）

```
unzOpenInternal 末尾调 unzGoToFirstFile（命中 1 次）
  → GetCurrentFileInfoInternal 首次调用失败（命中 1 次）
    → current_file_ok = false
      → 之后 4 次 unzLocateFile 全在
         if (!s->current_file_ok) return UNZ_END_OF_LIST_OF_FILE;   ← 原版 unzip.cpp:3247
         ⇒ unzStringFileNameCompare = 0、unzGoToNextFile = 0
```
四个数字（LocateFile=4 / GoToFirstFile=1 / Compare=0 / NextFile=0）**精确吻合**。
**下一轮唯一入口**：普查探针 **`0001111c`（`lufseek` 失败标记）** 一票区分
"seek 失败（⇒ `pos_in_central_dir` / `byte_before_the_zipfile` 算错）" vs "字段读短（⇒ fread）"。

## 六、诚实声明（我**没有**验证的 / **不可靠**的刻度）

1. **静态体积比不可当进度尺**（本项目第 16.43 条教训）：交集内 ±15% 命中仅 **53%（393/741）**，
   348 个超差 —— 但其中绝大多数是编译器习语（内联 / 冷热分割 / memset 尾调用 / 条件执行融合），
   **已登记豁免**。这个数字**不反映功能差距**，仅供参考。
2. **"741/804 已重编"不等于"功能正确"** —— 它只证明**符号落位**，不证明语义等价。
   语义等价目前只有 `prop_equiv`（213 个专有函数、**只能当探针**）+ 沙箱行为差集（9 场景、窗口有限）两份证据。
3. **沙箱里的"我们更成功"（124 vs 139）不是我们更强** —— 是工厂侧在沙箱里缺一环而早死。
   拿它当"我们更接近原厂"是错的解读。
4. **CI `bb104f61`（第二轮普查 26 地址）结果尚未出** —— 本报告成文时它仍在 `in_progress`。
   它只影响 §四"下一轮入口"的二分结论，不影响上表其余数字。
